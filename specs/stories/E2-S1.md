# E2-S1 — User and RefreshToken repositories

**Layer:** Repository
**Group:** B
**Depends on:** E1-S1, E1-S3

## Description

Implement persistence for authentication identities and refresh-token lifecycle. The User
repository stores email, Argon2 password hash, and theme preference; the RefreshToken
repository tracks issued tokens for rotation and revocation.

## Acceptance Criteria

1. `create_user(email, password_hash)` persists a User and returns it with a generated id; a duplicate email raises a typed unique-constraint error.
2. `get_user_by_email(email)` returns the matching User or None, and the lookup is case-insensitive on email.
3. `store_refresh_token` persists a token with an expiry timestamp; `revoke_refresh_token` marks it revoked so it cannot be reused.
4. `is_refresh_token_valid(token)` returns False for revoked or expired tokens and True only for active ones.
5. Repository methods accept an injected session and contain no HTTP or business-rule logic (verified by import boundary).
