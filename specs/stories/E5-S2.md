# E5-S2 — KnowledgeChunk ingestion, chunking, and pgvector indexing

**Layer:** Repository
**Group:** B
**Depends on:** E1-S1, E1-S3, E5-S1

## Description

Build the RAG knowledge base: ingest curated markdown (ATS, resume/profile, interview,
career material), chunk it, embed each chunk, and index the chunks with embeddings in
pgvector for similarity retrieval.

## Acceptance Criteria

1. An ingestion routine reads curated markdown KB files, splits them into bounded chunks (with source attribution per chunk), and persists KnowledgeChunk rows.
2. Each persisted chunk stores a 384-dimension embedding produced by the EmbeddingProvider.
3. A pgvector similarity query returns the top-k nearest KnowledgeChunks for a query embedding, ordered by similarity.
4. Re-running ingestion is idempotent: it does not create duplicate chunks for unchanged source files.
5. Each retrieved chunk retains its source reference so downstream RAG outputs can cite it.
