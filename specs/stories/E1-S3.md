# E1-S3 — Database connection, migrations, and pgvector setup

**Layer:** Repository
**Group:** A
**Depends on:** —

## Description

Provision the PostgreSQL data layer with the pgvector extension, a connection/session
factory, and a migration framework. This is the persistence substrate every repository
builds on, including the vector columns used for resume, job, and KB embeddings.

## Acceptance Criteria

1. A migration creates the database schema and enables the `pgvector` extension; running migrations from a clean database succeeds with exit code 0.
2. A connection/session factory yields scoped database sessions and is the single import point for all repositories.
3. Vector columns are declared with the correct dimensionality for the bge-small-en-v1.5 model (384 dimensions) on the Job, Resume, and KnowledgeChunk tables.
4. A health-check function executes `SELECT 1` and returns healthy/unhealthy status used by the API health endpoint.
5. Migrations are reversible: applying then rolling back the latest migration returns the schema to its prior state without error.
