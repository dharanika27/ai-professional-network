# E2-S3 — Auth API endpoints and middleware

**Layer:** API
**Group:** E
**Depends on:** E2-S2

## Description

Expose authentication over HTTP: register, login, refresh, and logout endpoints, plus
authentication middleware/dependency that protects routes and injects the current user.
Includes the application health-check endpoint.

## Acceptance Criteria

1. `POST /api/auth/register` with a valid email and password returns 201 and a body containing a non-null user id; a duplicate email returns 409.
2. `POST /api/auth/login` with valid credentials returns 200 with access and refresh tokens; invalid credentials return 401 with a generic message.
3. `POST /api/auth/refresh` with a valid refresh token returns 200 with a new access token; an invalid/revoked token returns 401.
4. A protected endpoint returns 401 when no/invalid bearer token is supplied and 200 when a valid access token is supplied.
5. `GET /api/health` returns 200 with database status when the system is healthy and a non-200 status when the database check fails.
6. Malformed request bodies return 422 with field-level validation detail and never a 500.
