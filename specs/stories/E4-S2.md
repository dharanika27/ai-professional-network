# E4-S2 — Resume parsing service (local extraction + LLM structuring)

**Layer:** Service
**Group:** C
**Depends on:** E4-S1, E6-S1

## Description

Hybrid resume parsing: deterministic local text extraction (pypdf / python-docx) followed
by LLM normalization into the structured schema {contact, skills, education, experience,
certifications, projects}. Enforces the upload policy and treats all extracted text as
untrusted input.

## Acceptance Criteria

1. The service accepts only PDF and DOCX files ≤5 MB, validating both MIME type and extension, and rejects anything else with an actionable error.
2. Password-protected, corrupt, or text-extraction-empty files are rejected with a specific user-facing error and never reach the LLM step.
3. Local extraction produces raw text via pypdf/python-docx; the LLM step structures it into the exact {contact, skills, education, experience, certifications, projects} schema and the output is schema-validated.
4. Invalid or incomplete LLM JSON triggers exactly one retry; a second failure returns a safe error without internal details.
5. Resume-borne prompt injection is neutralized: system instructions take precedence and adversarial in-resume instructions do not alter the structuring task (verified by an injection test fixture).
6. No resume text or PII is written to logs; only request id and metadata are logged.
