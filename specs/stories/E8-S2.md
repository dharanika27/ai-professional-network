# E8-S2 — Auth and onboarding screens (Landing, Register, Login, Onboarding)

**Layer:** UI
**Group:** G
**Depends on:** E2-S3, E8-S1

## Description

The entry-point screens: a marketing Landing page, Register and Login forms wired to the
auth API, and a multi-step Onboarding flow that seeds the initial professional profile.
Built on the design system with accessible forms.

## Acceptance Criteria

1. Registering through the Register screen calls `POST /api/auth/register`, stores the returned tokens, and routes the user into onboarding on success.
2. Logging in through the Login screen authenticates and routes to the dashboard; invalid credentials show an inline, accessible error without revealing whether the email exists.
3. Forms validate inline (email format, password length) and expose validation errors to screen readers via accessible markup.
4. The Onboarding flow collects initial profile fields and persists them, then routes to the dashboard.
5. All four screens render correctly in light and dark themes and at mobile/tablet/desktop breakpoints.
