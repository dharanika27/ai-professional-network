# E2-S2 — Authentication service (register, login, JWT, refresh)

**Layer:** Service
**Group:** C
**Depends on:** E2-S1

## Description

Implement the authentication business logic: registration with Argon2 password hashing,
login that verifies credentials and issues a JWT access + refresh token pair, and a refresh
flow that rotates refresh tokens. Designed for later Google OAuth extension without
refactoring.

## Acceptance Criteria

1. `register(email, password)` hashes the password with Argon2 (never stores plaintext) and rejects an already-registered email with a typed error.
2. `login(email, password)` returns a signed JWT access token (short TTL) and a refresh token only when the Argon2 verification succeeds; wrong password returns an auth error and never reveals whether the email exists.
3. `refresh(refresh_token)` issues a new access token and rotates the refresh token, revoking the old one; a revoked or expired refresh token is rejected.
4. Issued access tokens are JWTs whose payload contains the user id and an expiry claim, and are verifiable with the configured JWT secret.
5. Password complexity is validated (minimum 8 characters) and a too-short password is rejected before hashing.
