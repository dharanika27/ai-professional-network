# E4-S1 — Resume metadata repository and secure file storage

**Layer:** Repository
**Group:** B
**Depends on:** E1-S1, E1-S2, E1-S3

## Description

Persist resume metadata and store the uploaded file securely behind a storage interface
(local container volume for MVP, swappable for object storage). Tracks file hash for
caching of deterministic AI operations and supports user-initiated deletion.

## Acceptance Criteria

1. A storage interface abstracts file persistence so the backend (local volume) can be swapped without changing callers.
2. `save_resume` stores the file bytes and persists metadata (user id, filename, MIME type, size, SHA-256 file hash) returning a resume id.
3. `delete_resume(resume_id, user_id)` removes both the stored file and its metadata, and cascades to associated ResumeReview records.
4. Stored resume files are not placed in any web-served/public path (verified by storage location check).
5. Retrieving a resume by hash returns the existing record, enabling cache hits for unchanged files.
