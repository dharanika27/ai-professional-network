# E1-S2 — Centralized configuration and secret loading

**Layer:** Config
**Group:** A
**Depends on:** —

## Description

Externalize every configuration value into environment variables loaded through a single
typed settings object. This includes database URLs, JWT secrets, the Claude API key, LLM
model selection, token budgets, upload limits, and rate-limit thresholds. Centralizing LLM
config enables future provider switching and token budgeting without code changes.

## Acceptance Criteria

1. A single typed Settings object (pydantic-settings) loads all config from environment variables and validates them at startup.
2. The application fails fast at startup with a clear, actionable error message naming the missing variable when a required secret (DATABASE_URL, JWT_SECRET, ANTHROPIC_API_KEY) is absent.
3. No secret or API key appears as a literal anywhere in the source tree (verified by grep returning zero hardcoded keys).
4. LLM configuration is centralized: model id, max tokens, timeout (60s), and per-user AI rate limit are all read from settings.
5. Upload policy values (max size 5 MB, allowed types PDF/DOCX) are read from settings, not hardcoded in the service.
