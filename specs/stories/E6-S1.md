# E6-S1 — Centralized Claude LLM client with schema validation and guardrails

**Layer:** Service
**Group:** C
**Depends on:** E1-S2

## Description

A single Claude client wrapping all LLM access, applying the BRD's AI guardrails: schema
validation of outputs, one retry on transient/invalid output, safe user-facing errors,
request-id logging without PII, timeouts, and centralized model/token config. All AI
features call Claude only through this client.

## Acceptance Criteria

1. The client exposes a `complete_structured(prompt, schema)` method that validates the model's JSON against the provided schema and returns a typed object.
2. On invalid/malformed model output or a transient error, the client retries exactly once, then raises a safe error containing no internal/provider detail.
3. Every request is logged with a request id and metadata only; no prompt content, resume text, or PII is logged (verified by inspecting log output).
4. The client enforces the configured 60-second timeout and surfaces a graceful timeout error on overrun.
5. Model id, max tokens, and provider settings are read exclusively from centralized config, enabling provider/model switching without code changes.
6. The client supports a streaming completion mode usable by long tasks (resume review).
