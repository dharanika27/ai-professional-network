# E1-S1 — Define shared domain types and DTOs

**Layer:** Types
**Group:** A
**Depends on:** —

## Description

Establish the typed foundation for the entire system: domain entities (User, Profile,
Resume, Job, etc.) and the request/response DTOs that cross layer boundaries. These types
are the contract every other layer imports, enforcing one-way dependencies and giving the
builder a single source of truth for shapes.

## Acceptance Criteria

1. Pydantic models exist for every entity in the BRD data model: User, RefreshToken, Profile, Resume, ResumeReview, ProfileOptimization, Job, JobMatch, KnowledgeChunk, AIRequestLog.
2. The Profile model includes typed fields for headline, summary, skills (list[str]), education, experience, certifications, projects, and completion_percentage (int 0–100).
3. Request/response DTOs are separate from persistence models, so no internal field (e.g., password_hash) is exposed in any response DTO.
4. `mypy --strict` passes over the types module with zero errors.
5. The structured-resume DTO matches the BRD schema exactly: {contact, skills, education, experience, certifications, projects}.
